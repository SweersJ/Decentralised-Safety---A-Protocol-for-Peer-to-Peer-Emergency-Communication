## Quint proposition snapshot

```quint
    val payload_messages_are_pending_or_known_by_receiver =
        NODES.forall(
            sender => NODES.forall(
                receiver =>
                    isPeerPair(sender, receiver) implies
                    getPayload(sender, receiver).messages.forall(
                        m =>
                            // Still scheduled for this receiver
                            m.in(getNodeState(sender, receiver).messages)
                            or 
                            // No longer scheduled because the receiver already has it
                            m.in(getMessagesMessageStore(receiver))
                    )
            )
        )
```

## Formal verification formula

$$
\forall s,r\in N,\;s\ne r:\;\forall m\in P_{sr}.\mathit{messages}:\;m\in NS_{sr}.\mathit{messages}\lor m\in MS_r
$$

## Formal verification textual message

Every payload message is either still pending for its receiver or already stored by that receiver.

## Explanation

This ownership-and-progress consistency predicate accounts for the two legitimate reasons a message can remain in a payload. Before delivery it remains in the sender's per-receiver pending state; after storage it may no longer be pending but must be known by the receiver. A violation is an orphan payload message unsupported by either state.
